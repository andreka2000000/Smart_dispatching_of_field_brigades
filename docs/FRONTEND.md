# Frontend MaxTelecom

Next.js App Router, React, TypeScript, TanStack Query, MapLibre. Рабочие экраны по умолчанию подключены к Go API и PostgreSQL.

## Запуск

Из корня проекта при запущенном Docker Desktop:

```powershell
docker compose --profile routing up -d --build --wait
```

Интерфейс: http://127.0.0.1:3000. API: http://127.0.0.1:8080/api/v1/health. PostgreSQL: 127.0.0.1:15432. Данные сохраняются в Docker volume. Остановка: `docker compose stop`.

Если порт 3000 занят локальным Next dev:

```powershell
$env:FRONTEND_PORT='3001'
docker compose up -d --build --wait
```

Интерфейс будет на http://127.0.0.1:3001. Только для новой пустой базы можно загрузить примеры:

```powershell
docker compose --profile demo run --rm seed
```

**Повторный seed заменяет справочники и дни.** Для просмотра существующих данных повторять его не нужно. После загрузки выберите день в шапке диспетчерской и нажмите «Построить план». После первого события дальнейшие изменения вносятся через события.

## Разработка в WebStorm

Требуются Node.js 24 и npm:

```powershell
npm ci
docker compose up -d --build --wait postgres api
npm run dev
```

Входная страница: `src/app/page.tsx`, рабочая оболочка: `src/app/app/layout.tsx`. Скрипт `dev` из package.json запускает `next dev --hostname 127.0.0.1` на порту 3000. В WebStorm выберите npm run configuration → dev.

- `npm run check` — TypeScript, ESLint, тесты, production build.
- `npm run build` / `npm start` — production без Docker.
- `npm run generate:api` — типы из контракта организаторов.

## Страницы и дизайн

- `/` — отдельная русская главная MaxTelecom без зависимости от API.
- `/app/dispatch` — выбор дня, сводка, поиск, фильтры, карта, команда, Гант, журнал, ПГП и история предупреждений.
- `/app/technician` — маршрут выбранного мастера, остановки, заявки и сообщение об изменении.
- `/app/admin` — реальные сотрудники, нормативы, сервисные центры и состояние API.

Палитра соответствует главной: чёрный фон с мягкими фиолетовыми градиентами, фиолетовые границы и акценты, приглушённые поверхности. Цвета статусов сохраняют смысл. Есть мобильная раскладка.

Дизайн развивает согласованный макет https://dispatch-two-bay.vercel.app/ и собственную главную. Это локальная реализация, не экспорт исходников Vercel. Маркетинговые иллюстрации показывают примеры сценариев; кабинет абонента пока не реализован. Шрифты хранятся локально в `public/fonts` с лицензией OFL.

src/features/marketing/          главная, графика, роли
src/features/workspace/          реальные рабочие экраны
  context.tsx                    запросы, выбор дня, мутации, обновление снимка
  types.ts / model.ts            DTO и представление
  dispatcher.tsx                 диспетчерская
  technician.tsx / admin.tsx     мастер и администратор
  forms.tsx                      новая заявка и пять остальных типов событий
  panels.tsx                     расписание, детали, предупреждения

Прежние mock-экраны сохранены для отдельного визуального демо. В режиме API ошибка показывается явно; при потере связи последний успешный снимок сопровождается предупреждением. Подмены демонстрационными данными нет.

## Данные и API

Go API версии 0.9.0 предоставляет:

- `GET /ui/v1/days` — дни, модельное время, версия, число событий.
- `GET /ui/v1/days/{date}/workspace` — согласованный снимок справочника, дня, текущего плана и журнала в одной SQL-транзакции REPEATABLE READ. До первого расчёта `plan=null`.
- `POST /api/v1/days/{date}/plan` — первоначальный расчёт.
- `POST /ui/v1/days/{date}/events` — новая заявка, отмена, задержка, передача в подразделение, недоступность мастера, TIME_TICK.

Контракт организаторов не изменён. H1–H10, нормативы, навыки, ПГП и перепланирование принадлежат Go. Frontend не рассчитывает дорожное время. TanStack Query обновляет снимок после мутации и периодически перечитывает его.

Интерфейс использует **модельное время UTC+5**, а не часы компьютера. Метки «На объекте» и «Выполнена» основаны на подтверждениях исполнителя. Плановые состояния «Окно визита идёт» и «Ожидает подтверждения» показываются отдельно. GPS отсутствует.

Повтор того же события в открытой форме использует прежний event_id. После неизвестного результата запрос можно повторить без дублирования. Изменение тела создаёт новый идентификатор; закрытие формы завершает контекст повтора.

Новая заявка выбирает адрес из справочника и передаёт DTO серверу. Контрольный срок в рабочих днях указывается из обращения: календарь на клиенте не дублируется. Конкурентный конфликт номера отклоняется сервером; номер абонентского обращения уже выдаётся сервером. Преобразование обращения в выездной наряд остаётся отдельным следующим шагом.

## Подключение

Защищённые рабочие страницы используют реальные данные Go. Старые mock-компоненты сохранены в исходниках, но не подключены к рабочим маршрутам. Для локальной авторизации выполните `npm run auth:bootstrap`; используйте пустой NEXT_PUBLIC_API_BASE_URL и same-origin proxy.

Next.js проксирует запросы на серверный `API_PROXY_TARGET` (по умолчанию http://127.0.0.1:8080). В Compose используется http://api:8080. Настройка применяется при запуске, CORS между браузером и Go не нужен. Proxy работает в dev и standalone production, сохраняет HTTP-статусы и JSON ошибок. Таймаут — 330 секунд; хостинг с меньшим serverless-лимитом потребует другой схемы развёртывания.

Секреты нельзя хранить в `NEXT_PUBLIC_*`: эти значения доступны браузеру.

## Карта

Показаны координаты домов из справочника. Выбор заявки связан со списком и расписанием. Для выбранного сотрудника отображается автомобильный путь OSRM по дорожной сети; при отсутствии OSRM показывается ошибка без подмены прямой линией. Есть расстояние, время переезда и справочное прибытие до планового выезда. GPS и текущие пробки не подключены. Расписание рассчитывается Go по матрице организаторов.

MapLibre использует OpenStreetMap с атрибуцией. Для публичной нагрузки нужен подходящий tile-провайдер; правила: https://operations.osmfoundation.org/policies/tiles/.

## Следующий этап

Дорожные маршруты OSRM и оценка времени переезда без текущих пробок реализованы. PyVRP подключён к первоначальному планированию через Go. Рабочая диспетчерская показывает сравнение назначений и переездов либо резервный режим; поле optimization — локальное расширение Plan, исходная схема организаторов сохранена. После событий первоначальный отчёт не отображается как результат нового поиска. Вход, серверные права трёх ролей и приём обращений абонентов реализованы. Диспетчер включает полномочия администратора. Преобразование обращения в наряд и подтверждение выполнения реализованы. Далее — независимая и визуальная приёмка. Подробности: [ACCESS_AND_WORKSPACE.md](ACCESS_AND_WORKSPACE.md).
