# Дорожная маршрутизация MaxTelecom

MapLibre остаётся библиотекой отображения. Локальный OSRM строит автомобильный путь по OpenStreetMap и возвращает геометрию, расстояние и оценку времени. Подписки и ключи внешних routing API не нужны. Данные о текущих пробках отсутствуют.

## Первый запуск

Docker Desktop должен работать; локально нужен Node.js 24.

```powershell
npm ci
npm run routing:prepare
npm run demo:generate
npm run demo:load
```

Первый шаг подготовки однократно получает дорожные ways, узлы и ограничения поворотов из Overpass для области 56.65–57.05 N, 60.35–60.95 E. HTTP-запрос содержит только эту общую область, без данных сотрудников/абонентов. Выгрузка сохраняется в игнорируемой `work/routing`; после подготовки графа OSRM работает локально. Подложка карты OpenStreetMap пока по-прежнему загружается из интернета.

Версия образа OSRM 26.11.0 закреплена digest в compose.yaml. Контейнер `osrm-prepare` выполняет extract → partition → customize с двумя потоками; маркер `prepared` записывается только после успеха. Повторный запуск использует готовый граф. При обновлении области или версии сначала сохраните прежний каталог и готовьте новый граф отдельно; наличие старого маркера не означает, что обновлённый OSM уже обработан.

Учебный импорт создаёт отдельную БД `magistral_training`. Прежняя `magistral` и её события сохраняются. Скрипт записывает в локальный `.env` только API_DATABASE и FRONTEND_PORT, сохраняя другие настройки. Frontend по умолчанию открывается на http://127.0.0.1:3001/app/dispatch.

## Последующие запуски

```powershell
docker compose --profile routing up -d --build --wait
```

Повторная генерация и импорт не нужны. Выберите сотрудника в диспетчерской либо откройте `/app/technician`. В окне мастера автоматически показан его дорожный маршрут, ближайший переезд, расстояние, оценка времени и остановки смены. Изменение версии плана обновляет дорогу. До первоначального плана дорожный расчёт недоступен.

OSRM доступен только с хоста по http://127.0.0.1:5000. Для приложения внутри Compose используется `OSRM_URL=http://osrm:5000`. Если Go запускается вне Docker, задайте ему OSRM_URL=http://127.0.0.1:5000. Порт можно изменить через OSRM_PORT; для скриптов подготовки при этом задайте OSRM_SETUP_URL.

## Разделение обязанностей

- Go решает назначение и порядок остановок, обеспечивает H1–H10 и модельное время.
- `GET /ui/v1/days/{date}/staff/{staff}/road-route?generation=…&version=…` читает согласованный план и передаёт его точки OSRM. Клиент не присылает произвольный путь или URL провайдера.
- OSRM Route API сохраняет порядок точек. Trip API для переупорядочивания не используется.
- Соседние остановки в одной точке объединяются для запроса; исходные seq возвращаются в дорожных участках. Например, обратный переезд начинается после обеда, а не до него.
- Запросы разбиваются максимум по 64 точки, перекрывая соседние части одной точкой. Есть ограничение параллелизма, таймаут, объединение одновременных одинаковых запросов и ограниченный кэш.
- При ошибке OSRM сохраняются расписание и точки заявок, показывается недоступность дорожного пути. Прямая линия не выдаётся за дорогу.

Расписание организаторов всегда проверяется по загруженной матрице. Для нашего учебного набора сама матрица получена от того же OSRM; при загрузке другого набора дорожные оценки могут отличаться. Эндпоинт карты не изменяет план, его версию или журнал.

## Время прибытия и позиция

GPS пока не подключён. Расчёт переезда начинается от СЦ или последней остановки. До планового выезда можно показать справочное прибытие = конец предыдущей остановки + дорожное время. Когда по модельному плану мастер уже в пути, оставшееся время без GPS не выдумывается: показывается длительность всего участка и объяснение. Подпись «Без текущих пробок» обязательна.

## Проверки

`npm run check` проверяет frontend. `docker compose --profile test run --build --rm tests` проверяет Go с настоящей PostgreSQL, CSV/JSON полного набора, ошибки провайдера, кэш, разбиение длинных маршрутов и то, что просмотр дороги не меняет план. UI дополнительно проверяется на полном наборе 40/400. Это не замена нагрузочной приёмки на независимых сценариях.
