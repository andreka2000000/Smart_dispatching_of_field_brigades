# Синтетические данные MaxTelecom

Это собственный учебный набор команды, созданный потому, что организаторы пока передали только спецификацию API. Он не является официальным или скрытым оценочным набором.

Состав: **40 сотрудников (28 ЛТП и 12 инсталляторов), 5 СЦ, 50 узлов, 100 домов, 400 нарядов на 28 октября 2026 года, 8 типов работ**. Начальное модельное время — 08:30 UTC+5. Есть две смены, обед, разные технологии, допуски к высоте, неполный запас и вместимость оборудования, повторные обращения. Первые три ремонта — контролируемый пример ПГП.

Сотрудники, адреса, СЦ, распределение нагрузки и нормативы демонстрационные. Координаты учебных объектов привязаны к автомобильной сети Екатеринбурга. Названия адресов не утверждают наличие реальных абонентов в этих точках. Матрица направленная, 105×105: длительности и расстояния получены от локального OSRM и округлены вверх до целых секунд/метров. Текущие пробки не учитываются. Одинаковый seed и один и тот же дорожный граф дают тот же набор.

| Файл                   | Содержимое                                                                  |
| ---------------------- | --------------------------------------------------------------------------- |
| `service_centers.json` | Массив пяти СЦ                                                              |
| `staff.json`           | Массив 40 сотрудников                                                       |
| `access_nodes.json`    | Узлы с домами                                                               |
| `work_types.csv`       | RFC 4180, UTF-8 без BOM, списки профилей через `\|`, пустое значение = null |
| `travel_matrix.json`   | Направленная матрица секунд/метров                                          |
| `orders_train.json`    | Массив нарядов; импортёр выбирает нужный день и registered_at ≤ now         |
| `events_example.json`  | Четыре явных события и два триггера задержки/передачи по текущему плану     |
| `manifest.json`        | Seed, происхождение графа, дата и размеры набора                            |

Генерация из корня: `npm run routing:prepare`, затем `npm run demo:generate`. Загрузка: `npm run demo:load`. Она сначала валидирует весь набор, затем создаёт отдельную БД `magistral_training`, переключает API на неё через локальный `.env` и строит план. Исходная БД `magistral` сохраняется. Для явной повторной замены **только учебных данных**: `npm run demo:load -- --replace`. Обычный запуск не требует повторной загрузки.

Контрольный сценарий событий автоматически не проигрывается при импорте. Триггеры требуется разворачивать относительно фактических визитов: время и сотрудника берут из текущего плана, а не из заранее выдуманного расписания. При отсутствии визита триггер пропускают.

400 нарядов не обязаны поместиться в смены: жёсткие ограничения сохраняются, остаток явно учитывается в Unassigned/ПГП. Эффективность оценивается по качеству допустимого плана, а не требованию любой ценой назначить все обращения.
